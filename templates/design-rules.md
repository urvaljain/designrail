# Design rules

> **Starter guidance, not your design system.** DesignRail created this file as a starting point.
> Replace or edit every section so it describes what your team actually agreed on.
> Machine-checked rules live in `designrail/config.yaml`; tokens in `designrail/tokens.json`;
> components in `designrail/components.json`.

## Tokens

- Use the semantic tokens registered in `designrail/tokens.json` (CSS variables or Tailwind keys listed there).
- Do not introduce new raw colors, spacing values, or font families. If a needed value is missing, say so and
  propose a token instead of inventing one.

## Components

- Reuse components registered in `designrail/components.json` before writing raw HTML equivalents.
- Do not add props or variants to a component unless the task asks for it.
